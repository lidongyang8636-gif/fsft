## 1 你必须做的四件事

1. **独立复核 P0 的三条关键结论**（**不许采信自述**）：
   ① 宿主**不会** fail-open（handler 抛异常 / 返回 `undefined` ⇒ **工具被堵死**；永不 settle ⇒ 卡死）；
   ② **不调 `next()` 会否决链上其余 listener**（连内置默认都不跑）；
   ③ `return {kind:'allow'}` **不是**放行，而是"**静默覆盖别人的更严判定**"。
   ⇒ 用 `rt-probe.mjs` 复跑，**或自构造**（如认为它的探针本身有偏差）。
2. **实际构造 ≥3 条绕过路径**（给**具体输入/命令 + 观察结果**）。**优先打它点名的三条**：
   `REDTEAM-NOTES §1`（`run_tcl` 在 MCP 通道内任意执行）、`§5/§6`（伪造证据 / 时间戳自报）、`§3`（跨任务挪用，**无任务↔产物绑定**）。
3. **反向打（误伤面）**：造"**它会不会拦住合法操作**"的场景 —— 尤其 `§11`：`ask` 在**无 agent / 无 approval 服务**的上下文里**退化成 `deny`**（它自己标了这是**读实现的推断、未实机观察**）。请判断这个"更严"是否可接受、会不会把正常工作流变成不可用。
4. **判 `REDTEAM-NOTES.md` 是否诚实**：有没有**漏报它已知的洞**、有没有**把小洞说成大洞**、有没有**把"没做缓解"包装成"已缓解"**。
