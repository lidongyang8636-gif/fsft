# FSFT · Full-Super-FPGA-Team

**一套让多个 AI agent 在同一个真实工程里安全协作的分层纪律。**

名字里的 FPGA 是它第一个真实战场（电机控制 + 传感器 + Vivado 上板），**不是适用范围**。
只要能落到"有产物、有验收、有不可逆动作"的工程上，这套分层就是通用的。

---

## 它解决什么

多个 agent 一起干活，真正的失效点不是"谁更聪明"，而是四类结构性错误：

| 失效 | 后果 | 由哪一层防 |
|---|---|---|
| **身份错配**：谁都能改、谁都在改 | 互相覆盖，事后无法复现 | **I** 身份层 |
| **能力越界**：只读角色手里握着写能力 | 边界靠自觉，等于没有 | **C** 能力层 |
| **匆忙交付**：没证据就往下走 | 烧错位流、上错板 | **F** 摩擦层 |
| **做了但不知道对不对** | 把干净日志当验收 | **T** 观测层 |

一条硬判据：**每一层必须同时具备"独立的失效模式"和"独立的拦截机制"。**
没有自己拦截机制的东西不配单独成层 —— 所以"成本 / 路由"被拆进 T1/T2 两个子域，而不是新立第五层。

---

## 结构

> **一份静态权威 ＋ 一层确定性注入 ＋ 三件执行件 ＋ 一条路由规则。**

| # | 件 | 落在哪 | 说明 |
|---|---|---|---|
| 1 | **静态权威**（团队架构） | [`ARCHITECTURE.md`](ARCHITECTURE.md) | 我是谁 / 遵守什么 / 怎么通信 / 工具怎么用。单一权威，禁止复制正文 |
| 2 | **确定性注入**（常驻 context） | [`AGENTS.md`](AGENTS.md) | 每轮必须遵守的纪律。注入是确定的，检索是概率的 —— 纪律不能只放在检索里 |
| 3 | **执行件**：能力 / 摩擦 / 观测 | [`guards/`](guards) | 身份与能力裁剪、产物机械闸、事件日志 |
| 4 | **路由规则**（角色 → 模型） | 由调度方在派单时钉死 | 本仓只给规则，不含实现 |
| 5 | **记忆索引**（经验与判据） | 仓外 | 坑、判据、为什么这么定。按需召回，**不承担"必须遵守"** |

## 一次任务怎么流

```
① 注入       AGENTS.md（确定性）＋ 画像 curated block（确定性）＋ 角色卡（按角色）
      ↓
② 身份解析   我是谁（Lead / writer / reviewer / 子代理）
      ↓
③ 能力裁剪   roleScope + shellScope + tools.restrict   ← 真正的边界
      ↓
④ 模型路由   角色优先 → 任务关键词兜底（显式指定最高）
      ↓
⑤ 干活       写文件 / 调 MCP / 跑工具
      ↓
⑥ 摩擦闸     证据绑定产物 + 产物探针（时序 / DRC）→ ask / deny / pass
      ↓
⑦ 落证据     gate/evidence/** ＋ decisions.log（每次判定一行）
      ↓
⑧ 沉淀       事实 / 技法 / 决策，带日期与证据指针
```

**读法**：②③④ 是**准入**，⑥ 是**出口**。②③ 失效 → 越权；④ 失效 → 干错活；⑥ 失效 → 烧错东西。**四者互不替代。**

## 五个必须定的决策

| 编号 | 决策 | 结论 |
|---|---|---|
| **D1** | SSOT 归属 | 文件是权威，记忆库只是索引。**禁止双向复制正文** |
| **D2** | 常驻预算 | 分载体计量：纪律文件 **≤60 行**、画像 block **≤20 行**。新增常驻必须删一条或降级为指针 |
| **D3** | 角色 → 模型 | 角色优先，任务兜底，派单时显式指定最高 |
| **D4** | 统一机械闸 | 一条判定链、三类探针（身份 / 新鲜度 / 体检）、一份日志 |
| **D5** | 能力层优先于摩擦层 | 真正的边界是"拿不到能力"，不是"再多问一次"。闸只做减速带 |

## 目录

```
AGENTS.md          确定性注入的纪律（唯一权威）
ARCHITECTURE.md    组织架构（单一权威）
docs/              思路、手册、落地记录、实验与提案
guards/            护栏插件参考实现（见下方边界）
reviews/           审查与红队记录 —— 架构是被吵出来的
```

**`guards/` 是参考实现，不是可独立运行的包。** 它依赖特定的 agent 框架（插件 API、宿主事件、工具层），离开那个环境跑不起来。读它是为了看**判定逻辑怎么写**，而不是为了直接跑。

其中 `guards/rule-router` 与 `guards/effort-check` 属**成本层（T2）**，其配置未随仓发布 —— 这一层本身就是可替换件，用别的路由/预算插件完全可以替代。

## 边界（诚实声明）

本仓记录的是**架构与判据**，不是可 `npm install` 就能用的产品：

- **未随仓发布**：`config/`（成本层配置）、`scripts/`（与本机运行环境强绑定的验证脚本）、`slices/`（过程档案）
- **不可直接运行**：`guards/` 依赖宿主框架；`docs/` 中的路径占位符（`%USERPROFILE%` / `%MAIN_REPO%`）需替换为你的实际路径
- **未完成项**：D3（角色→模型）已冻结；D4 的产物 hash 绑定与配置 sha256 入审计未做 —— 详见 [docs/FSFT-架构_v2.md](docs/FSFT-架构_v2.md) §6、§8
