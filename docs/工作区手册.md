## 2. 沙箱与提权（本工作区最重要的一节）

### 2.1 可写范围

```text
%MAIN_REPO%-dsh          ← 本工作区。沙箱内可直接读写，无需提权。
%MAIN_REPO%              ← 主仓库（含四棵工作树）。沙箱内【只读】。
   ├─ .worktrees\{frontend,backend,device,integration}
   ├─ .git / .agents / .codex
```

**读主仓库不需要授权**（随便读、搜、diff）；**写主仓库 = 提权**（改源码、写证据、跑 `gradlew`、`git add/commit/worktree`、联网都要批）。

### 2.2 工作方式：产出与落地分开

1. **在本工作区干活**：草稿、分析、补丁、证据整理、脚本——不需提权，可反复试；
2. **要进仓库时算一次提权**：批量写进对应工作树，或执行 `git`；
3. 提权是「**批量、有意识**」的动作，不是每条命令点一次。

### 2.3 明确禁止

- 为让某条命令跑通而**关沙箱 / 改权限 / 放宽安全设置**；
- **手改 ACL / 完整性标签**（需要改可写范围时报告，由用户决定）；
- **手改 `%USERPROFILE%\.dsh\storages\workspace.json`**（DSH 内部存储；加工作区走 GUI）；
- **无差别提权**——先问"这个写入真该进仓库吗"，能放工作区就放工作区。

### 2.4 开工自检（落地第一件事）

```powershell
Set-Content '%MAIN_REPO%-dsh\.selfcheck.txt' 'ok'; Remove-Item '%MAIN_REPO%-dsh\.selfcheck.txt'
Set-Content '%MAIN_REPO%\.selfcheck.txt' 'x'   # 预期被拒
```

| 结果 | 含义 | 处置 |
|---|---|---|
工作区可写、主仓库被拒 | **正常** | 继续 |
两处都可写 | 沙箱未生效（可能在提权模式） | 确认是有意提权，否则报告 |
两处都被拒 | 沙箱把工作区也拒了 | **停下报告**，不要自己改权限 |

> 2026-10-08 曾有"根可写、18 个子目录不可写"的中间态（完整性标签未继承），已修复；快照见 `%MAIN_REPO%-dsh-acl-backup-20261008\acl-before.txt`。

## 3. 工作树与分支（主仓库布局）

```text
%MAIN_REPO%                master
└─ .worktrees
   ├─ frontend      codex/frontend      Android
   ├─ backend       codex/backend       Spring Boot + Web
   ├─ device        codex/device        ACX720 / MicroBlaze / FPGA
   └─ integration   codex/integration   三端联调
```

合并只有两个方向：`master`→枝（同步基线）、枝→`master`（收口）；**枝之间不互 merge**，要合流先回根再分发。本仓库无远端，推送/发布需单独授权。**一条分支同时只能被一棵工作树检出**（报 `already used by worktree` 属正常护栏）。

因主仓库只读，**建工作树/切分支/add/commit 都要提权**；提权命令用**显式路径**，禁止 `git add -A`。

**`verify-all.mjs` 说明（2026-10-21 新增）**：

- 覆盖 **G1 静态契约**（profile YAML 可解析、`restrict` 模式合法、`hard ⇒ agentScope` 必开、`quotaFallback` 字段与档位合法、effort 声明缺口=0 **且 `unknown` 族不得声明档位**）+ **G2 八套单测**（role-guard 6 + rule-router 2）+ **G3 分类器一致性**（`bad=0`）。
- **清单显式枚举，不自动 glob** —— `scripts/` 里多数是一次性工具（有的会改文件），`guards/_retired_20261021/` 下还有退役测试，自动发现会假红 + 有副作用。
- 退出码 `0` = 全绿；任一 FAIL 则 `1`。缺文件按 **FAIL** 计（不许静默当绿）。
- **它不等于机械闸**：`gate-guard` 判**产物**（上板前），`verify-all` 判**护栏代码与配置**（改完后）。
- 想用篡改副本做变异检验：`VERIFY_PATCH=<另一份 patch> node scripts/verify-all.mjs`。
- **机器可读输出**（2026-10-21 加）：
  - `node scripts/verify-all.mjs --json` → stdout 输出纯 JSON（`{ok,total,passed,failed,durationMs,failedItems[],results[]}`），退出码不变。
  - `node scripts/verify-all.mjs --json-out=.cache/va.json` → **脚本自己用 UTF-8 写文件**（推荐）。
    ⚠ 别用 PowerShell 的 `> file` 重定向抓 JSON —— 它按 UTF-16 写盘，文件不是合法 JSON（实测踩过）；`cmd /c "... > file"` 是字节级重定向，可用于验 stdout。
- `--verbose` 的细节行走 **stderr**（保证 `--json` 时 stdout 是纯 JSON）。

### 5.1 护栏可恢复性（2026-10-21 新增）

**问题**：`~/.dsh/guards/` 在**沙箱外、不在 git**，丢了或换机就重建不了。

**做法**（镜像进仓库 + 双向校验，避免"假安全"）：

| 命令 | 作用 |
|---|---|
`node scripts/backup-guards.mjs` | 把 4 个运行版护栏（role-guard / gate-guard / subagent-sandbox / guard-ui）镜像到 `guards/_live_mirror/`，写 `MANIFEST.json`（每文件 sha256 + 整树 treeHash） |
`node scripts/restore-guards.mjs` | **默认 dry-run**：先自检镜像完整性，再报告差异（`写入:` / `覆盖:`），运行版多出的文件**不删** |
`node scripts/restore-guards.mjs --apply` | 真正恢复；完成后再跑 `verify-all` 复核 |
`verify-all` 的 **G4** | **双向防漂移**：① 镜像文件 vs MANIFEST（备份没坏）② 运行版 vs MANIFEST（改了护栏没备份）——任一不符即 FAIL |

**纪律**：**改了 `~/.dsh/guards/` 里任何文件，必须立刻重跑 `backup-guards.mjs`**，否则 G4 会红。
只备份不校验 = 假安全；这是 G4 存在的唯一理由。
（`guards/rule-router`、`guards/effort-check` 在工作区内、本来就有 git，**不在镜像范围**。）

文档改动后链接门禁须保持 `LINK_CHECK_RESULT: ALL PASS`；实机记录落到 `设备项目文件/tests/` 的**日期化**文件（预期 / 接线 / 版本 / 原始日志 / 实际结果）。**这些命令都写主仓库 ⟹ 都要提权**。

### 5.2 会话存档审计（2026-10-21 新增 · `REVIEW.FSFT-2` F2 / F15）

**为什么需要**：`tools/pre-execute` **看不到** `read` / `write` / `send_message` / `team_task_*`（它们在 agent preset 层），

| 命令 | 回答什么 |
|---|---|

**两个实测坑**（踩过，别再踩）：

1. **存档是多帧 zstd**：`zlib.zstdDecompressSync` **只解第一帧**（12 MB 只出 203 B）⟹ 必须按魔数 `28 B5 2F FD` 切帧逐帧解；
   现已收进 `scripts/lib/session-archive.mjs`（**唯一解码实现**，两个 audit 脚本共用）。
2. **`send_message` 的参数名跨版本不同**：旧版 `agent_id`、新版 `target` ⟹ 解析要回退，否则一半消息显示"收件人未知"。

### 5.3 版本树（A′：共享主仓库对象库的只读挂载，2026-10-21 建）

**问题**：本工作区此前**不在任何 git 里** —— `~/.dsh/guards` 有镜像兜底，`docs/` 与 `scripts/` 没有。但整目录 **46 478 文件 / 3.5 GB**（`_probe` 522 MB、`fpga_out` 2.4 GB、gradle 缓存、Vivado 日志、docx/zip 实验件）⟹ 全量入库既慢又无 diff 价值。

**形态**：

| 件 | 位置 | 作用 |
|---|---|---|
`.git` | 工作区根（**是文件**，不是目录） | 指向 `.git-fsft` |
`.git-fsft/` | 工作区内 | 独立对象库，**可整体删除回滚** |
`.git-fsft/objects/info/alternates` | → `%MAIN_REPO%/.git/objects` | **只读**共享主仓库全部历史（**不复制对象**）|
分支 | `fsft-workspace`（孤立根） | **永不合并**进 `master` |
`.gitignore` | 白名单 | 只收 SSOT / 文档 / 脚本 / 配置 / 护栏镜像 / 切片文档（**243 文件**）|

**能做什么**：`git log`、`git diff main/master -- <path>`、`git blame`、机械提交。
**推送（2026-10-21 已做）**：本库 `fsft-workspace` 已推到主仓库**同名分支** ⟹ 主仓库 `git log fsft-workspace` 能看到这两条提交；**master 与四个工程分支不受影响**。后续推送：`git push mainrepo fsft-workspace`（**需提权** —— 写主仓库 refs）。

**谁可以提交这棵树（2026-10-21 用户裁定）**：**只有 Lead**。writer / 审查者 / 分析员**一律不碰** ——
他们操作的是工程 worktree，不是本工作区；本条**不写进工程的 `TASK_TEMPLATE`**（不给他们增加无关入口）。

**机械提交**：

```bash

node scripts/fsft-commit.mjs -m "docs: ..."     # 暂存 + 提交 + 打印 stat
```

⚠ **白名单的代价**：在 `docs/ scripts/ reviews/ config/ guards/ slices/` **之外**新建的文件**默认不进版本**。要纳入就改 `.gitignore`（新增一类目录比放行单个文件更稳）。

**回滚**：`rm -rf .git .git-fsft` ⟹ 回到"无版本控制"，**工作区文件一个不动**。

### 5.4 路由接管 / 让位（2026-10-21 新增）

**现象**：`rule-router` 按任务关键词路由；你在 composer **手选**了模型，它下一次 `pre-step` 仍会按规则拉回 ——
「我选了东西它也要卡我」。

**现在的语义**：**手选即让位**（本会话不再切换），**接管要显式**（不是下一条命令自动恢复）。

```bash
node scripts/router-mode.mjs           # 看状态 + 最近的 yield/resume
node scripts/router-mode.mjs auto      # 接管（恢复按规则路由）
node scripts/router-mode.mjs manual    # 强制让位（排障用）
node scripts/router-mode.mjs clear     # 删开关 ⟹ 回到自动检测（默认）
```

| 机制 | 说明 |
|---|---|
落点 | `.rule-router/mode.json`（`{"mode":"auto"\|"manual"}`），插件按 mtime **热读** |
手选检测 | 会话投影 `modelSelection.pending`（`/model` 与 UI 手选都走它）|
**不猜** | 取不到投影 ⟹ **不让位**（宁可继续路由，也不误判）|
审计事件 | `router-yield`（`reason: manual-pick` / `manual-file`）、`router-resume` |
自测 | `guards/rule-router/test/manual-override.mjs`（M1–M5，已进 `verify-all` G2）|

**按钮入口（2026-10-21 加）**：设置页 →「Guard 设置」→ **路由接管（rule-router）** 一组三个按钮：
**接管**（写 `auto`）/ **让位**（写 `manual`）/ **清除**（删文件 ⟹ 自动检测）。
走的是 `POST /guard/api/router.mode`（`action: get|auto|manual|clear`），与 `guard-ui` 其它设置**同一围栏**
（loopback + origin + JSON），**不另开写通道**。
