## 2. 数据流：一次任务从进入到上板

```
① 注入         AGENTS.md（确定性） + curated block（确定性，≤20 行） + 角色卡（按角色）
                 ↓
② 身份解析     role-guard：我是谁（Lead / writer / reviewer / 子代理）
                 ↓
③ 能力裁剪     role-guard.roleScope + shellScope + tools.restrict   ← 真正的边界
                 ↓
④ 模型路由     rule-router：角色优先 → 任务关键词兜底（显式 spawn 指定最高）
                 ↓
⑤ 干活         （写文件 / 调 MCP / 跑工具）
                 ↓
⑥ 摩擦闸       gate-guard：证据绑定产物 + 产物探针（时序/DRC）→ ask/deny/pass
                 ↓
⑦ 落证据       gate/evidence/**  + decisions.log（每次判定一行）
                 ↓
⑧ 沉淀         记忆库（事实/技法/决策），带日期与证据指针
```

**读法**：②③④ 是**准入**，⑥ 是**出口**；②③ 失效 → 越权；④ 失效 → 干错活；⑥ 失效 → 烧错东西。**四者互不替代**。

## 3. 常驻 context 的策略（直接回答"记忆库还是 Architecture 指针"）

**结论：纪律进文件注入，经验进记忆库；两者用锚点互链，不互相复制。**

| 内容类型 | 归谁 | 理由 |
|---|---|---|
| **必须每轮遵守的纪律**（不变量、停止线、安全边界） | **`AGENTS.md`**（确定性注入） | 注入是**确定**的；检索是**概率**的。把纪律放检索里 = 纪律可能"没命中" |
| **组织关系 / 通信协议 / 工具用法** | **`ARCHITECTURE.md`**（指针） | 长文、改动低频；注入只放"指针 + 何时必须读全文" |
| **坑、判据、历史为什么这么定** | **记忆库**（semantic） | 这类内容**按需召回**即可，且天然带日期与证据 |

**当前问题**：常驻有 **2 个源**（AGENTS.md 全文 + curated block），而 `AGENTS.md` 自己已写"画像只保留开工前五条、两者不复制"——**规则有了，预算没有**。

**建议预算（硬数字）**：
- **常驻 ≤ 60 行**：`AGENTS.md` 只留 **①4 条不变量 ②停止线 ③角色卡三行 ④到 ARCHITECTURE 的指针**；细则移进 `ARCHITECTURE.md` 的对应节，注入里改成"要做 X 必须先读 ARCHITECTURE §Y"。
- curated block **≤ 20 行**，只放"用户当下的硬口径"（现状大致如此）。

> 理由不是省 token，而是你定过的：**注意力预算是硬约束**。注入里每多一条"也许有用"，就少一分"必须守住"的注意力。

## 4. 五个必须定的决策

### D1 · SSOT 归属（**建议：文件是权威，记忆库是索引**）
`ARCHITECTURE.md` = 组织架构唯一权威；`AGENTS.md` = 纪律唯一权威；记忆库**永不作为"必须遵守"的载体**（它是证据库）。
互链方式：记忆条目里写 `见 ARCHITECTURE §X`；`ARCHITECTURE` 里写"证据见记忆库门牌 YYY"。**禁止双向复制正文**。

### D2 · 常驻预算（**建议：≤60 行 + 指针化**）
见 §3。任何新增常驻，必须同时删一条或降级为指针。

### D3 · 角色 → 模型（**建议：角色优先，任务兜底，显式最高**）
现状 `rule-router` 是**任务关键词**路由（`verilog`→sol、`docx`→luna），**没有角色维**。而你记忆里的硬口径是「writer 用便宜档、sol 只给异构审查槽位」——这是**角色规则**，现在只能靠"spawn 时定档"实现。
目标优先级：**① spawn 显式指定（已实现 `skip-explicit-route`）> ② 角色声明 > ③ 任务关键词 > ④ default**。
配套：`subagent-model-selection-settings.allowedModels` 是"白名单"，应升级为"**角色→允许集合**"，否则白名单管不住"哪个角色该用哪档"。

### D4 · 统一机械闸（**建议：一条判定链，三类探针，一份日志**）
把三段并成**一次判定**，输出同一种 verdict：

| 检查类 | 现在的实现 | 并入后 |
|---|---|---|
| **身份**（这对产物是哪一对） | `preboard-gate.py` identity + hash | probe `identity`（产物 sha256 == 记录值） |
| **新鲜度**（源比产物新？） | 同上 freshness + `bitstream_gate.tcl` | probe `freshness`（产物 mtime > 源 mtime） |
| **体检**（这份产物达标吗） | **无人管** ← `s8-r54` 的洞 | probe `quality`（同 run 报告必须 `All user specified timing constraints are met`） |
| 证据绑定 | `gate-guard` 收口证据（无身份关联） | 收口证据必须**点名产物 hash** |

**统一格式**：`VERDICT · check=identity|freshness|quality · target=<产物> · basis=<原文行> · evidence=<路径>`。

### D5 · 能力层优先于摩擦层（**已完成：restrict 与闸各司其职**）
`gate-guard` 拦 13 个工具名，而 `run_tcl` 能绕开（代码注释自认）。真正的边界是**让只读角色拿不到能力**：`tools.restrict` 掉 shell / MCP 写工具。**闸只做"再问一次"，不承担"拦住"。**

**已成对落地（2026-10-21 验收）** —— 能力层是**两个机制**，互补而非替代：

| 机制 | 作用点 | 强度 | 覆盖 |
|---|---|---|---|
`roleScope`（`role-guard` 全局） | **dispatch 前拦截** | 硬 | 全部 MCP 调用（含子代理继承角色） |
`hard`（`restrictMcpWriteTools`） | **工具面移除** | 硬（对该 agent 的继承层） | 继承层 921 个可限制名中的 498 个写类 |

⚠ **掩面 ≠ 拦截**：`restrict` 只覆盖**继承层**；`read`/`write`/`pwsh`/`send_message` 属 **agent preset 自身层**，**掩不到**。
⟹ 执行侧仍由 `roleScope` + **文件沙箱**兜底；"看不见"只是降低误用概率，不是安全边界。

## 5. 一个新的结构结论：**代码不可写，配置可写，配置哈希入审计**

护栏代码已在 `~/.dsh/guards/`（agent 改不动，实测 `WRITE-DENIED`）。但**判据数据必须能快速迭代**（探针、白名单、豁免）——如果也放保护目录，每次调参都要重启。

所以分两处：

| 东西 | 位置 | 谁能改 | 可审计性 |
|---|---|---|---|
| 护栏**代码**（判定逻辑） | `~/.dsh/guards/` | 只有用户 | 改 = 重启 + 自哈希告警 |
| 护栏**配置**（probes / 白名单 / 豁免） | 工作区 `config/guards/*.yml` | agent 可改 | **每次判定把配置文件的 sha256 写进 decisions.log** ⟹ 改配置是**可见**的，不是静默的 |

这条是本次搬迁带来的直接收益：**以前"改闸"和"改判据"是同一件事且都静默；现在它们分开了，一个变难、一个变可见。**

### 8.2 成本/路由归位：**T 层拆两个子域，不单立 E 层**（2026-10-21 定）

`rule-router` 现在具备"上游 **402**（包月额度耗尽）→ 切 `%PAYG_PROVIDER%` **按量**档"的兜底（`quotaFallback`）。
它此前**不属于 I/C/F/T 任一层**，现归位如下：

| 子域 | 关心什么 | 机制 | 失效模式 |
|---|---|---|---|
| **T1 观测** | 做了什么、做得对不对 | `guard-events.jsonl`、`decisions.jsonl`、gate 探针 | **盲区**（preset 层零记录，见 §8.1） |
| **T2 策略** | 用谁做、**花谁的钱**、还能不能花 | `rule-router`（规则路由 + `quotaFallback`） | 额度耗尽整轮失败、成本失控 |

**为什么不单立 E 层**（三条）：

1. **层的数量由"独立失效模式 + 独立机制"决定**。`I` 防错配、`C` 防能力越界、`F` 防匆忙、`T` 防"做了但不知道对不对"。
   成本/路由**没有自己的拦截机制** —— 402 时不阻止任何动作，只换 provider 重试 ⟹ 本质是**资源观测 + 执行策略**。
2. **单立 E 会诱发误读**：让人以为有"第五道安全边界"。实际它连减速带都不是（额度耗尽 ≠ 危险动作被拦）。
3. **但直接塞进 T 会混掉两类东西**：审计（事后可查）与策略（事前选路）⟹ 必须显式划子域（上表）。

**一条硬边界**：**T2 只管"可用性与成本"，不得用于安全判定**——不许用"省钱"当拒绝理由，
也不许因为切了按量档就放松任何 `C` / `F` 层判据（换 provider 不换护栏）。
