# 把「闸」融进 guard 插件：可行性与必要性（2026-10-21）

**模式**：`ANALYZE`（只读）。未改代码、未跑 Vivado、未上板。
**前提**：本项目（smart_home）已收尾、验收已过。本评估的收益对象是**下一个同类 FPGA 工程**，不是给本项目补作业。

---

## 1. 现状：现在其实有**两道闸**，判据不同、位置不同

| | `guards/gate-guard`（宿主插件） | `smart_home/slices/_common/preboard-gate.py`（项目脚本） |
|---|---|---|
| 挂在哪里 | `tools/pre-execute`（宿主工具调用前，**能拦住 MCP 烧板**） | 命令行，**人自觉去跑** |
| 管什么 | 13 个烧板/位流/固化类 MCP 工具 | 一对产物（位流 + ELF）的身份与新鲜度 |
| 判据 | 有 `gate/evidence/close-*.md` → 引用 JSON 证据 → `gateOk===true` 且 `PASS>0`；`pins` 哈希无漂移；**证据时间严格晚于产物 mtime**；产物必须是"有效普通文件、非空、非链接" | `board-identity.json` 记的 SHA-256/大小逐项比对；**mtime(bitstream) > 最新 rtl/constr**；另跑三个子脚本（status_view / four-layer-strings / not-run-index） |
| 拦不住什么 | **证据与产物无身份关联**（`03` 原文：SPEC L390「证据与该产物之间没有任何身份关联」）；**不看产物内容**（那份位流时序过没过，它不知道） | 管不到 MCP 工具（靠人记得跑）；`resolve_bitstream()` 只搜 `fpga_out/s8-*/bitstream/*.bit`，**进不到 `build2/bitstream`** |

**两道闸都在判"新不新鲜"，都不判"这份产物本身好不好"。** 这正是昨天 r54 事件暴露的洞。

---

## 2. 必要性：三条证据，都来自本项目实测

1. **时序不满足的位流就在"规范路径"上**：`s8-r54/bitstream/smart_home.bit`（13:37:29）对应报告 **WNS = −40.037、7 个失败端点、`Timing constraints are not met.`**；而时序通过的那份（`build2/bitstream/`，`4AA9323D…`，WNS +11.034）**深一层、闸搜不到**。两份**字节数完全相同**。⟹ 只靠"新鲜 + 有收口"，完全可以烧到一份**时序不满足**的位流。
2. **证据可以"借"**：`gate-guard` 的 pass 条件是"有新鲜绿证据 + 能绑定一个有效产物"，但证据是**任务级**的，不校验"这份证据是否在说这份位流"。⟹ 任何无关任务的收口（例如 `docs-links-r2`）都能解锁烧板 —— 这一点 `03` 已自承。
3. **新鲜度是自报的摩擦，不是边界**：两处都用 mtime。`build2` 那次重建把 mtime 推后了 30 分钟，"更新"了但产物没进 `bitstream/`；mtime 比较对"哪一份是现行件"毫无约束力。

**结论**：不是"两个闸重复所以合并省事"，而是**两处都缺同一块**：**产物身份（唯一性 + 是哪一份）与产物体检（这份文件自身的质量）。** 这块补进去，才叫把闸做完整。

---

## 3. 可行性：三个方案，成本与风险差很多

| 方案 | 做法 | 成本 | 风险 | 评价 |
|---|---|---|---|---|
| **A. 合并成一个** | 把 `preboard-gate.py` 整体搬进 `gate-guard`，插件内 `spawn python` | 中 | **高**：`gate-guard` 现在是**纯 JS、零子进程**，这是它可靠的原因之一；引入子进程 = 超时/编码/路径/沙箱 四类新故障面；且会把 smart_home 的目录结构写死进通用插件 | ❌ 不建议 |
| **B. 反向合并** | 在 `preboard-gate.py` 里加"时序/DRC 体检" | 低 | 低 | 治标：命中项目脚本层，**管不到 MCP 烧板**（人不跑就等于没有） |
| **C. 分层（推荐）** | `gate-guard` 保持"策略与绑定"；新增**纯 JS 的产物探针**阶段：配置一串 `{name, file, mustMatch[], mustNotMatch[], maxAgeMs}`，pass 前必须全部满足 | 中（约 80–120 行） | 低（只加读文件 + 正则，无子进程） | ✅ 建议 |

### 方案 C 的具体形状（可直接落到现有代码结构里）

`classifyBurnCall()` 现在返回 `pass/ask/deny`。在 `pass` 之前插一个 `probeArtifacts()`：

```
probeArtifacts({ artifacts, probes, root })
  → 每个 probe: 读 file（不存在 = ask，不静默跳过）
                要求 mustMatch 全部命中、mustNotMatch 全部不命中（fail-closed）
                可带 maxAgeMs（artifact mtime 与 probe file mtime 的先后）
  → 任一不满足 = deny（附原文片段），不是 ask（这是"产物坏了"，不是"缺证明"）
```

配套两条**绑定**规则（直接治 r54）：

1. **产物唯一性**：同一次烧写候选里出现**多个** `.bit`（或同名不同目录）⟹ `ask`，并把候选路径全列出来让人选；不许静默取"第一个"或"最新 mtime"。
2. **产物—报告配对**：探针配置要求"位流所在 run 目录里必须有一份 post-route timing 报告，且写 `All user specified timing constraints are met`"。r54 案例在 `ask` 阶段就会被拦下（canonical 路径那份的报告说 `not met`）。

### 不推荐把 `preboard-gate.py` 那三个子脚本塞进插件的原因

`status_view.py` / `four-layer-strings.py` / `not-run-index.py` 是**项目证据体系**的一部分（解析 slice 目录、frozen json、HANDOFF 段落），与"烧板这一刻该不该放行"不是一回事。它们的产出应当**被**闸引用（作为一条 probe 的输入），而不是被闸实现。

---

## 4. 建议的落地顺序（如果要做）

1. **先做绑定，不碰体检**：产物唯一性 + 报告配对（这两条就能挡住 r54 这一类）。约 40 行，零新依赖。
2. **再做探针**：`probes` 配置项 + `mustMatch/mustNotMatch`。约 60 行。
3. **最后才是接项目脚本**：把 `preboard-gate.py` 的**输出摘要**写成一个文件，闸只读该文件（一条 probe），不调用它。
4. **`gate/SPEC.md` 必须同步更新**：现在写着"证据与产物无身份关联"，改完要写清"关联到什么程度、还不管什么"，否则又是文档落后于实现。

---

## 5. 明确不做（以及为什么）

- **不把 `preboard-gate.py` 搬进插件**：跨语言 + 项目耦合，换来的只是"少手工跑一次"。
- **不用闸去判"位流能不能上板"**：时序/DRC 是**工具报告**的判据，闸只做"报告里有没有那句话"的机械核对；判据本身仍归报告。
- **不改 mtime 语义**：新鲜度是摩擦，不是安全边界 —— 这句话 `03` 已经写死，别再往它身上加期望。
- **本项目不回填**：项目已验收，改 guard 属于"下一个工程的基建"，不应触发对 r54/r23 的任何重做。

---

## 6. 一句话结论

**必要**：现有两道闸都在判"新不新鲜"，**都不判"这份产物本身对不对、是不是它"**，r54 已经证明这能烧到时序不满足的位流。
**可行**：用**纯 JS 探针 + 产物唯一性/配对**（方案 C）约 100 行即可，**不要跨语言合并**（方案 A 风险大于收益）。
